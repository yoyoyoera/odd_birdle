# 하루 도전(Daily Challenge) 설계 (사용자와 합의한 내용, 2026-11-19)

## 합의된 것
- 매일 하나의 "비틀기"(규칙)가 모두에게 같게 나온다. 셔틀콕·효과는 그대로 랜덤. 후보 8종(`daily.js`): Windy Day, Sudden Death, Smash Fest, Five in a Row, The Post, Moving Net, Shrinking Bird, No Warning. (Hot Air, Tiny Bird, Take the L, Chaos, 추가 규칙들은 뺌. 2v2 가 완성되면 후보에 추가 가능.)
- 시도 횟수: 하루 5회(`dailyAttempts`). **Sudden Death 는 1회만.** (5~10회 사이에서 5로 시작, 조정 가능.)
- 순위는 **깬 순서**(그날 몇 번째로 클리어했는가). 클리어 시간은 순위와 별개로 카드에 표시. 순위는 확정되면 바뀌지 않는다(그래서 `OF N` 같은 표시는 쓰지 않음).
- 깬 사람만 카드를 만들 수 있다. 모든 카드에 순위를 넣고, 1~3등은 금·은·동 색 테두리와 큰 순위 탭(`card-rank.js`)으로 강조. 탭에는 `RANK`와 **그날 날짜**(예: `NOV 19`)를 넣는다.
- 카드: `CLEARED` 크게, 클리어 시간, 닉네임 크게, 점수는 작게(`card.js`의 daily 레이아웃). 도전별 모티프 그림은 시도했으나 군중만이 낫다고 판단해 뺐다(`card-motifs/` 는 빈 자리만 남김).
- 연승(스트릭)은 하지 않는다. 대신 날짜별 ✓ 달력.
- 리셋 시각은 UTC 0시(한국 오전 9시) 추천. 순서 순위는 리셋 직후 접속한 사람에게 유리하다는 점을 인지.

## 위조(조작) 방지 — 구현할 때 지킬 것
게임 계산은 브라우저에서 돌기 때문에 완벽한 방지는 불가능하다. 목표는 "간단한 위조를 어렵게".
1. **서버가 기록의 주인.** 시도를 시작할 때 서버가 시도 토큰(유저·날짜·도전·시각)을 발급해 저장하고, 끝났을 때 클라이언트가 보낸 결과를 서버가 검증한다. 클리어 시간은 클라이언트가 말한 값이 아니라 **서버가 잰 시작~종료 시간**을 쓴다.
2. **불가능한 기록 거르기.** 목표 점수에 비해 너무 짧은 시간, 이미 쓴 토큰, 시도 횟수 초과, 날짜가 다른 도전은 거절. 순위는 Redis 의 원자적 증가(INCR)로 부여해 중복·경쟁 조건이 없게 한다.
3. **카드는 서버 기록에서만.** 카드 올리기 API 는 서버에 저장된 클리어 기록이 있을 때만 동작하고, 댓글 글자(순위·시간·날짜)는 **서버가 기록에서 직접 만든다**. 이미지는 클라이언트가 그리지만 크기·형식을 제한한다.
4. **앱 계정의 확인 답글.** 사용자의 카드 댓글 아래에 앱 계정(u/odd-birdle)이 "✓ Verified: Daily #12 · #3 · 0:43.3" 답글을 단다. 직접 만든 가짜 이미지 댓글에는 이 확인이 없으므로 구별된다. (`runAs: 'APP'`)
5. 속도 제한(유저당 시작/완료 호출), 입력 크기 제한, 계정·게시물 삭제 시 기록 삭제.
- 못 막는 것: 게임을 자동으로 대신 쳐 주는 봇, 시뮬레이션을 따로 돌려 얻은 기록. 더 막으려면 서버에서 입력 기록을 재생해 검증(결정적 시뮬 + `game.js` 재사용)해야 하는데 비용이 커서 해커톤 범위 밖.

## 만들 것 (순서)
1. `dailyFor(date)`: 날짜 → 도전(비틀기 + CPU 레벨 + 목표 점수) 결정 함수와 테스트.
2. 시도 시작/완료 API, 시도 횟수, 클리어 순서 순위(Redis), 날짜별 ✓ 달력.
3. 매일 게시물 자동 올리기(Devvit 예약 작업), 결과 화면의 카드 버튼(깬 사람만), 서버 확인 답글.
4. 도전 이름을 카드에 더 눈에 띄게(그림 대신 글자).

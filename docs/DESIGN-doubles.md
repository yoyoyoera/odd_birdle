# 2대 2(Doubles) 설계안 (스테이지 8·13·18·21)

사용자 요청: 나(사람) + CPU 파트너 vs CPU 2명. **한 팀 안에서 번갈아 쳐야 하고, 같은 사람이 연속으로 치면 반칙.**
지금 스테이지 표(`stages.js`)에는 `mode: 'doubles'`, `doubles: { partner, opponents }` 메타와 싱글 대체 규칙(`fallback: true`)이 이미 있다. 엔진이 지원하면 `fallback` 을 풀고 실제 2v2 로 돌린다.
온라인 대전은 이번 범위에서 제외(Reddit 앱은 CPU 전용).

## 1. 규칙 (추천 기본값)
- 팀: 왼쪽 = 사람(A) + 파트너 CPU(B), 오른쪽 = CPU C + CPU D. 한쪽에 라켓 둘. 라켓끼리는 서로 통과(충돌 없음).
- **차례**: 팀마다 `nextHitter` 가 있다. 팀이 셔틀콕을 한 번 칠 때마다 다음 차례가 다른 사람으로 바뀐다(A→B→A…).
  차례가 아닌 사람이 셔틀콕에 닿으면 **그 팀의 반칙, 상대 득점**(사유 `wrong partner`).
- 랠리 시작: 서브하는 팀의 첫 타자는 팀의 A(왼쪽 팀은 사람, 오른쪽 팀은 C), 받는 팀의 첫 차례는 팀의 A. 포인트가 끝나면 다시 이 값으로 초기화.
- 차례 표시(필수): 차례인 라켓에 작은 고리(●) 또는 밝은 테두리. 사람이 차례를 모르고 반칙하지 않게 한다. 상대 팀도 같은 표시(CPU 반칙이 보이면 재미).
- 득점·목표 점수·효과는 지금과 같음. 효과 중 차례 영향: SHOCK·트램펄린·범퍼로 방향이 바뀌어도 "마지막으로 친 팀" 기준은 같고 차례도 그대로.

## 2. 엔진 변경 (`game.js`)
- 라켓 저장소: 지금 `rackets.left/right`(키가 side). 키를 4개(`left`, `leftB`, `right`, `rightB`)로 늘리고 **팀(side)은 키에서 뽑는다**(`teamOf(key)`). `lastHitter`·`support`·`touching`·`hitCooldown` 은 side(팀) 단위를 유지하되 "누가 쳤는지"(`lastPlayer`)를 추가.
- 관련 위치: `moveRacket(side, input, frame)`(약 957행), `moveCpu`(986행), `checkContact`·`launch(vx, vy, hitter)`(829행), `serve`(387행), `view()`(`left`/`right` 필드 → `leftB`·`rightB`·`turn` 추가).
- 반칙 판정은 접촉 시: 접촉한 키가 `nextHitter` 가 아니면 `finishPoint(otherTeam, 'wrong partner')`.
- 파트너/상대 CPU: 지금 `moveCpu` 는 한 명. **라켓 단위 CPU 로직**(역할: 차례일 때 쫓아가 치기, 차례가 아닐 때 비켜서 대기)으로 일반화. 차례가 아닌 CPU 는 셔틀콕 낙하 지점에서 일부러 떨어져 서 있어야 한다(접촉 금지). 차례인 CPU 는 기존 `cpuPlan`·`flyForward`·`returnShot` 을 그대로 사용.
- 파트너의 움직임: 사람 라켓과 겹치지 않게 반대편 구역에서 대기(사람이 코트 어디에 있든 사람 위치의 반대 쪽 절반에 서기).
- 규칙 입구: 스테이지 규칙에 `doubles: { partner: 레벨, opponents: 레벨 또는 [C, D] }`. 없으면 지금과 동일(싱글).

## 3. 클라이언트 (`client.js`, `playback.js`, `index.html`)
- 입력은 그대로 사람 라켓 하나(`left`)만 움직임. 나머지는 게임이 움직인다.
- 그리기: 4개 라켓. 파트너는 내 라켓과 같은 연두색(조금 옅게), 상대 둘은 갈색. 차례 표시 고리.
- 반전 코트(`cpuMirrored`)·모바일 터치·작은 프레임에서도 보기 좋아야 한다(4개 라켓이 겹쳐 보이지 않게 크기·투명도).
- 스테이지 안내 문구에 규칙을 한 줄로: "Take turns hitting with your partner."

## 4. 테스트·측정
- 단위: 차례 번갈음, 차례 아닌 사람의 접촉 = 반칙·상대 득점, 포인트 후 차례 초기화, CPU 파트너가 차례가 아닐 때 접촉하지 않음(수천 틱 시뮬로 확인), 효과(SHOCK·범퍼·트램펄린)가 있어도 규칙이 깨지지 않음, 기존 싱글 테스트 전부 통과.
- 난이도: `tools/stage-difficulty.mjs` 확장(자동 사람 플레이어가 차례를 지키도록). 스테이지 8·13·18·21 승률 확인.
- 육안: 헤드리스 스크린샷(작은 프레임·모바일 세로·반전 코트).

## 5. 일정·위험
- 가장 비싼 작업(반환점은 4번: 라켓 키 일반화). 목표: 12/1 쯤 시제품(스테이지 8 하나가 돌아감), 12/5 전 네 판 완성.
- 위험: CPU 둘 + 파트너가 서로 방해(차례가 아닌 CPU 가 셔틀콕에 닿아 반칙), 사람이 차례 표시를 놓침. 안 되면 `fallback` 싱글 규칙으로 돌아가므로 제출은 안전하다.
- `game.js`·`client.js` 는 main(Code2)도 수정하므로 추가형으로 작게, `reddit` 브랜치에서만 작업.

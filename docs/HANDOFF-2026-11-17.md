## 3. 재경기 규칙: 현재 확정 동작

사용자가 웹과 itch에도 양쪽 준비를 요구했다. 이제 다음 출처가 한 명이라도 포함된 방은 양쪽 모두 준비해야 재경기를 시작한다.

- `site`: HTTPS `oddbirdle.pages.dev` 및 하위 도메인
- `itch`: HTTPS `itch.io` / `itch.zone` 및 하위 도메인
- `y8`: HTTPS `item-cdn.y8.com`
- `gamepix`: HTTPS `gamepix.com` 및 하위 도메인
- `gamedistribution`: HTTPS `html5.gamedistribution.com`, `revision.gamedistribution.com`

코드 방과 QUICK MATCH 모두 적용한다. 로컬 개발 서버도 동일하게 양쪽 준비를 요구한다. 변경 범위는 위 출처이며, 별도 취급되는 다른 포털까지 일괄 변경한 것은 아니다.

서버는 첫 `restart`를 준비 완료로 기록하고 `rematch_wait`를 각 플레이어에게 보낸다. 양쪽 준비가 모이면 준비 집합을 초기화하고 다음 라운드의 3초 카운트다운을 보낸다. 구버전의 `{ type: 'restart' }`도 호환되고, 최신 클라이언트는 `round`를 함께 보내 오래된 요청을 거부할 수 있다.

### 화면 안내

- 내가 먼저 준비: `Waiting for opponent…`
- 상대가 먼저 준비: `Opponent ready. Play again?`
- 준비한 쪽의 재경기 아이콘은 숨겨 중복 입력을 막는다.
- 새 경기 또는 방 나가기에서 준비 상태·문구를 초기화한다.
- 접근성 버튼 이름은 온라인에서 `Ready for rematch`, CPU에서 `Restart`다.

**기존 코드에 문구 문자열은 있었지만 `#status.sr-only`에만 들어가 실제 화면에는 안 보였다.** 이번에는 별도 `#rematch-status`를 만들고 아이콘 아래에 표시했다. 네트 선이 글자를 가리지 않도록 코트색 배경을 준다. 따라서 서버 배포만으로 구버전 포털에 문구가 생기는 것은 아니다. 각 포털 ZIP을 교체해야 화면 안내도 적용된다.

관련 파일: `origins.js`, `server.js`, `client.js`, `index.html`, `tests/gd-rematch.test.js`, `tests/cross-portal.integration.test.js`.

## 5. GamePix: 허가·음소거·랜덤매치

### 제출과 외부 서버 허가

- 지원 티켓 **#10156460**에서 Clause 3.3의 외부 멀티 서버 연결에 대한 서면 승인을 받았다.
- 사용자가 서버 도메인 `oddbirdle.pages.dev`, WebSocket `wss://oddbirdle.pages.dev/play`, Cloudflare 호스팅을 재확인하는 답장을 직접 보냈다.
- 지원팀은 HTTPS `*.gamepix.com` Origin을 허용하라고 안내했다. 오늘 앞선 배포에서 이미 반영되었고, 이번 변경도 유지한다. 도메인 유사 문자열과 HTTP는 허용하지 않는다.
- GamePix 전용 ZIP 최상위에 `index.html`이 있으며 소스·별도 기술 문서 제출은 요구하지 않는다고 답변받았다.
- 개발자 대시보드: https://my.gamepix.com/games/odd-birdle
- Game ID: `OEIDOB`. 현재 JavaScript SDK v3 초기화에는 별도 gameId 주입이 없다.
- 제출 설정: Odd Birdle, English, Sports, Desktop 켜기, Mobile 끄기, Landscape, HTML5-JS, SDK integration. 사용자는 Game URL 방식도 확인했지만 현재는 SDK 포함 **Upload a build** 방식으로 진행 중이다.
- Game URL 방식도 SDK 통합과 변경 시 재심사가 필요하므로 자동 광고나 심사 우회 수단이 아니다.

### 소리 경고 수정

실제 Player 테스트 화면에서 다음 경고가 나타났다.

```text
SOUNDOFF_GAME_FUNCTION_HAS_NOT_BEEN_DECLARED
SOUNDON_GAME_FUNCTION_HAS_NOT_BEEN_DECLARED
```

SDK v3의 `pause` / `resume` 이벤트만 연결해 놓았고, Player가 별도로 호출하는 레거시 `GamePix.soundOff` / `GamePix.soundOn` 콜백이 없었던 문제다.

이번 `portal.js`는 두 콜백을 등록하고 `sdkMuted`를 일시정지 상태와 별도로 관리한다.

- soundOff: 소리만 끄고 경기를 정지시키지 않는다.
- soundOn: 일시정지 상태를 강제로 해제하지 않는다.
- resume: Player가 꺼 둔 소리를 강제로 켜지 않는다.
- 게임 자체 음소거 선택은 `sound.js`가 계속 별도로 보존한다.

`tests/gamepix.test.js`에서 겹치는 mute/pause 이유를 검사했다. 실제 GamePix Player에서 최신 제출본의 Sound off/on까지 독립 검증한 것은 아니다. **현재 Review 심사는 유지하고**, 이 미확인 사항 때문에 임의로 Draft 교체·심사 취소를 하지 않는다. 검수 피드백이나 이후 사용자의 요청에 따라 확인한다.

### 랜덤매치 오해 해소

사용자는 처음 ‘웹과 멀티가 안 된다’고 했지만, 확인 결과 CREATE/JOIN 문제가 아니라 랜덤매치였다.

- 실제 GamePix 미리보기에서 만든 방에 공개 웹이 입장했고 **양쪽 초기 카운트다운**을 확인했다.
- 사용자는 이후 **랜덤매치도 연결되는 것을 직접 확인**했다.
- 따라서 이 증상을 GamePix의 외부 서버 미승인이나 Origin 차단으로 처리하지 않는다.
- QUICK MATCH는 양쪽 모두 QUICK MATCH에 들어가 있어야 하며, 탭이 visible이고 최근 30초 이내 입력이 있는 플레이어만 대기열에 남긴다. GamePix pause/광고 중에도 대기열에 남기지 않는다. 같은 브라우저의 탭을 번갈아 열면 백그라운드 쪽이 빠져 테스트가 안 잡힐 수 있다.
- 이번에는 대기가 비활성화된 이유를 `Matchmaking paused` 또는 `Move to keep searching…`로 설명하도록 보완했다. 실제 매칭 조건을 느슨하게 바꾼 것은 아니다.

GamePix 광고는 기존의 **3경기 완료 + 최소 3분** 간격을 유지한다. 사용자 조작으로 경기 사이에서만 요청하며, 광고 Promise가 끝나기 전에 준비 완료를 보내지 않는다. 별도 CONTINUE 화면은 추가하지 않았다.

## 6. GD와 Y8: 반드시 지킬 제약

### GD

- 원래 매 재경기마다 광고를 요청하던 설계는 바꿨다. 현재는 첫 진입 광고 1회, 이후 **최소 2분 경과 + 완료된 경기의 재경기 클릭**에서만 요청한다.
- 모드 변경·방 재입장만으로 추가 광고를 요청하지 않는다. 랠리·득점 중 광고는 없다.
- 실제 광고 후 CONTINUE 화면은 사용자가 그대로 두기로 했다. 임의로 제거하지 말 것.
- Game ID: `e2d1ed4845d7412a976f3337355b1d7b`.
- 외부 멀티 서버 및 향후 Steam·모바일 출시 조건에 관한 GD 답변은 아직 대기 중이다. **GamePix 승인과 혼동하지 말 것.**
- GD는 Draft 상태로 유지하고 실제 광고 포함 2인 재경기 테스트·답변 확인 후 활성화를 판단한다. 이번 세션에서는 심사 요청하지 않았다.
- 보상형 광고 예시 PDF는 별도의 코인·부활 시스템을 추가하라는 요구가 아니다. 현재 보상형 광고는 구현하지 않았다.

### Y8

- **이미 심사 중이라 현재 제출 파일을 교체할 수 없다. 사용자가 여러 번 강조했다. 심사 취소나 당장 재제출을 지시하지 말 것.**
- 제출본은 광고 뒤 restart를 보내지만, 구형 20초 타임아웃 때문에 긴 광고가 끝나기 전에 준비 완료가 나갈 수 있다.
- 서버의 양쪽 준비 규칙은 이미 적용되지만 서버는 실제 광고 종료를 관측할 수 없다. 이 한계를 서버만으로 완전히 해결했다고 말하면 안 된다.
- 신규 Y8 ZIP에서는 광고가 시작되면 fallback 타이머가 readiness를 풀지 못하게 했고, 이번 눈에 보이는 대기 안내도 포함했다.
- **신규 ZIP은 보관하고 심사 후 교체 가능해졌을 때 반영**한다. 지금 제출본에는 대기 안내도 없다.

## 8. 검증 결과와 다음 순서

- 최신 자동 테스트 **134개 전부 통과**. 추가된 실제 클라이언트 Pause 통합 검사는 위의 정책 문서를 참고한다.
- 실제 로컬 WebSocket: 5개 출처의 모든 25개 순서 조합을 **코드 방 / QUICK MATCH 양쪽에서 검사**했다. 총 50개 시나리오, 각각 첫 경기와 연속 두 번의 재경기다. 가속된 테스트 시계이며 실제 광고 검증은 아니다.
- 실제 Chrome: 최신 웹과 지정 itch 수정본으로 로컬 경기 종료 → 웹만 준비 → 화면에 waiting, 상대 화면에 opponent ready → 상대 준비 → 새 카운트다운을 확인했다. DOM에서 문구가 `hidden=false`, display block, 실제 높이가 있는지도 확인했고 스크린샷으로 육안 확인했다.
- 공개 웹은 앞선 ready-rematches 배포 소스와 일치한다. 최신 GamePix Pause 변경은 ZIP으로만 준비했으며 공개 웹에 재배포하지 않았다.
- **공개 서버 웹↔웹, 웹↔itch** 경기 모두 자연 종료(11:12) 후 한쪽의 구형 restart만으로 시작되지 않았고, 양쪽 준비 뒤 3초 카운트다운을 확인했다. 이 공개 검증은 프로토콜 클라이언트를 사용했다.
- 공개 GamePix↔웹은 실제 브라우저 첫 입장을 확인했고, 사용자가 랜덤매치 연결도 확인했다.

다음 할 일:

1. 사용자가 새 itch ZIP을 업로드하면 실제 itch 페이지에서 CREATE/JOIN 및 대기 문구를 확인한다.
2. GamePix와 Y8는 현재 심사를 유지하고 결과·피드백을 기다린다. 임의로 제출본을 교체하지 않는다.
3. 이후 검증이 필요한 경우 실제 Player Sound off/on, pause/resume, 새 탭 audio test와 실제 광고 중 재경기 readiness 순서를 확인한다. 플랫폼 mute 중 게임 버튼으로 강제로 소리가 켜지지 않아야 한다. 단위 테스트나 프로토콜 테스트를 실제 광고 재생 검증으로 표현하지 않는다.
4. GD는 답변과 검증 완료 전까지 활성화 보류. CrazyGames·Newgrounds는 반려 상태를 보존하고 사유 확인 없이 재제출하지 않는다.
5. main으로 통합할 때는 기존 다른 세션 변경을 확인하고 브랜치 내용을 합친다. 서버·클라이언트를 과거 버전으로 되돌리지 않도록 주의한다.

어시스턴트는 외부 메일 추가 전송이나 포털 심사 요청·심사 취소·파일 교체를 실행하지 않았다. **GamePix Review 제출은 사용자가 직접 수행하고 완료를 알렸다.**

## 9. 사이트 관리 봇 (추가 작업)

사용자가 홍보·사이트 관리의 번거로움을 줄일 봇을 요청했고, 선택지에서 **게임 사이트 관리**를 선택했다. SNS 자동 게시는 범위에 포함하지 않았다.

- 별도 브랜치 `work/promotion-bot`에 `tools/site-manager/`를 추가했다. 게임 코드와 현재 심사 제출 ZIP은 변경하지 않았다.
- 실행: `node tools/site-manager/bot.mjs`. Node 22 이상, 추가 패키지 없음. `run.command`로도 실행 가능하다.
- 공개 웹·itch 접속/제목, itch 제목 검색·지정 목록 노출, 선택적 공식 itch 누적 지표/Cloudflare 7일 이벤트를 한국어 보고서로 정리한다. 이전 정상 수집값과 비교하며 네트워크 실패나 미연결을 방문자 0으로 표시하지 않는다.
- 정식 GitHub 릴리스 노트가 있을 때만 개발일지 초안을 만들고 ID·본문 해시로 중복을 피한다. 커밋을 실제 배포로 단정하지 않으며 itch 배포 여부는 게시 전 확인한다. 현재 GitHub 정식 릴리스는 없어 업데이트 글을 생성하지 않았다. 별도 첫 소개 글 `itch-intro-draft.md`는 공개 itch 기능 설명으로 준비했다.
- 공식 itch API에 개발일지 게시 엔드포인트가 문서화돼 있지 않아 **자동 게시 미구현**이다. 이 기능이 완성됐다고 설명하지 않는다. 브라우저 계정 연결/쿠키를 추출하지 않았다.
- API 키는 실행 환경변수로만 읽고 코드·보고서에 저장하지 않는다. 오늘 실제 실행에는 itch/Cloudflare 키가 없어 해당 지표는 ‘연결 전’으로 남겼다.
- 실제 실행에서 공개 웹·itch HTTP 200 및 itch 제목 검색 링크를 확인했다. 스포츠 목록 요청은 HTTP 403으로 ‘확인 불가’가 맞다. 브라우저·검색 도구에서 보인 목록 결과와 서버 HTTP 요청 결과를 혼동하지 않는다.
- 봇 6개 회귀 검사 포함 전체 **140개 테스트 통과**. 일반 셸에서는 기존 WebSocket 테스트의 listen이 EPERM으로 막혀, 네트워크 허용 런타임에서 전체를 재실행해 통과했다.
- 출력 디렉터리는 git 제외. HTML만 요청하므로 게임 내 이벤트·광고를 실행하지 않지만 플랫폼 페이지 조회에는 잡힐 수 있어 6시간 이내 재요청 방지와 동시 실행 잠금을 적용했다.

추가 요청: 이 작업을 마친 뒤 **Y8 / GamePix / itch / 웹 / GameDistribution 일괄 업데이트 봇의 가능 여부만 조사**하기로 했다. 사용자는 ‘지금 당장 만들자는 뜻은 아니다’라고 명시했다. 배포 봇을 구현하거나 다섯 곳에 업데이트를 실행하지 말 것.

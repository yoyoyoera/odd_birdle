## 4. 찾은 것과 아직 의심되는 곳

**찾은 것 (고침)**
1. 실제 Y8 SDK는 Y8 밖에서 `showAd` 후 "Ad is initializing, waiting..."만 찍고 콜백을 하나도 안 부른다. 1.0.1은 3번째 경기 이후 재경기 클릭이 **20초 동안 무반응**(`giveUp` 20000). Y8 안에서도 같은 일이 생기면 반려 원인일 수 있다. 3초로 줄임.
2. (1.0.1엔 없고 이후 main에 생긴 회귀) 진 뒤 밖을 클릭하고 돌아오면 PAUSED 안내가 결과 화면을 덮고 첫 클릭을 먹었다. 고침.

**아직 확인 못 함 — 다음에 볼 곳**
1. **진 순간에만 도는 코드가 Y8 iframe에서 예외를 던져 `client.js` `frame()` 루프가 죽는 경우.** `frame()` 안 어디서든 예외가 나면 `requestAnimationFrame(frame)`에 도달하지 못해 화면 전체가 영구 정지한다. 후보: `sound-cues.js`의 'lose' 큐 → `sound.js` `play()`(오디오 컨텍스트 상태), `crowd.js`(finished 시 applauseBig·cheer), `confetti.js`, `juice.js`. 헤드리스 테스트는 `--autoplay-policy=no-user-gesture-required --mute-audio`로 돌려 오디오 경로가 실제와 다를 수 있다. 안전장치로 `frame()` 본문을 try/catch로 감싸 예외가 나도 다음 프레임을 예약하게 하는 것을 권한다.
2. Y8 실제 페이지에서 광고가 **실제로 뜨는** 경우(beforeAd 후 afterAd/adBreakDone 순서), Y8 로그인(`autoLogin: true`)·동의(CMP) 창이 뜨는 경우.
3. "Adapts to any size" 설정에서 Y8이 iframe 크기를 바꾸거나 전체화면으로 전환할 때.

## 5. 테스트 도구 `tools/y8-lab`

```
cd tools/y8-lab && npm i
node ../../scripts/build-portal.mjs y8      # 최신 Y8 빌드(portal/y8)
node prepare.mjs                             # games/ 에 ready(1.0.1)·new·*-local 준비
node static.mjs &                            # 8770 호스트, 8771 게임(서로 다른 origin)
node relay.mjs &                             # 온라인 테스트용 로컬 matchmaker(8772)
node flow.mjs ready cpu none                 # <ready|new> <cpu|quick> <none|blur|blurhover> [mobile]
node online.mjs new-local                    # 두 명 온라인
node ad.mjs ready                            # 실제 Y8 SDK 광고 경로
node layout.mjs                              # iframe 크기별 버튼 위치
```

- Chrome 경로는 기본 `/Applications/Google Chrome.app/...`, 다르면 `CHROME=` 환경변수.
- 한 판 지는 데 1~2분 걸린다. 동시에 8개까지는 `static.mjs`로 문제없었다(파이썬 http.server는 동시 요청에서 연결을 끊어 오탐을 냈다).
- 결과 줄 끝의 `OK restarted` / `STUCK after restart click` 으로 판정. 페이지 오류는 `page errors:` 줄에 모인다. 404 두 개는 SDK가 찾는 파일이라 무시해도 된다.

## 7. 후속 조사와 재제출 후보 (11월 19일)

**Y8 검수 때 발생한 원인은 여전히 미확인이다.** 아래 두 경로에서는 같은 증상을 재현했다. 첫 번째는 SDK 콜백 순서를 제어했고, 두 번째는 브라우저 예외를 주입했다. 검수자의 기기나 실제 광고에서 그 조건이 발생했다는 증거는 없다.

| 조건 | 검수본 1.0.1 | 1.0.3 후보 |
|---|---|---|
| 광고 시작 대기 만료 → 재경기 시작 → SDK의 늦은 beforeAd → afterAd | 종료 신호 뒤에도 isPaused()가 true. 1.0.2도 동일 | 실제 광고 중에는 멈추고 종료 신호에서 재개 |
| CPU 패배가 HUD에 표시된 첫 효과음에서 AudioBufferSourceNode.start가 한 번 예외 발생 | 재경기를 눌러도 8초 뒤까지 화면이 finished | 라이브 랠리에 진입하고 MENU로 복귀 |
| 패배 화면에서 CanvasRenderingContext2D.fill이 한 번 예외 발생 | 비교 미실행 | 라이브 랠리에 진입하고 MENU로 복귀 |

- 광고 요청 대기의 종료와 실제 광고의 종료를 분리했다. 중복 시작, 이미 끝난 요청, 다음 광고로 넘어간 뒤 도착한 이전 요청의 콜백을 무시한다. 3초 시작 대기와 90초 종료 대기는 유지했다.
- 공통 클라이언트는 프레임에서 예외가 발생하면 시간 누산기와 캔버스 상태를 초기화하고 다음 프레임 한 개를 예약한다. 오류는 브라우저 콘솔에서 확인할 수 있으며 출력은 5초당 최대 한 번이다. 게임 점수·승패를 초기화하지 않는다. 지속적으로 실패하는 브라우저 기능 자체를 복구하는 기능은 아니다.
- 회귀 검증은 루트에서 `node --test tests/`로 실행한다(162개 통과). 위 5절의 준비·서버 실행 후 `tools/y8-lab`에서 `node finish-recovery.mjs ready audio stuck`, `node finish-recovery.mjs new audio recovered`, `node finish-recovery.mjs new canvas recovered`로 브라우저 비교를 재현할 수 있다. 일반 패배 대조군은 두 번째 인자로 `none`을 사용한다. 브라우저 기본 오디오 제스처 정책과 실제 CPU 경기를 사용한다.
- 소스 기준은 main의 d9618d1. 수정 브랜치는 `y8-finish-recovery`. 검증용 ZIP은 `oddbirdle-y8-1.0.3-candidate.zip`이며 SHA-256은 `6c1b2391418888444d4e1bb4a0b38fad571736c4cf6e1eba9cebbf4938d10140`이다. 이 후보의 Y8 제출 여부는 사용자가 결정한다.
- 실제 Y8 SDK v2.18.0도 로컬 iframe에서 확인했다. 광고가 콜백 없이 초기화 대기에 머물렀을 때 약 3.0초 후 재경기 대기가 풀렸고 일시정지는 해제 상태였다. 이 측정은 Y8 사이트에서 광고 영상이 실제 노출된 경우를 검증하지 않는다.
- 무작위 CPU전에서 수정본 두 판은 150초 후에도 경기 중이라 패배 후 동작을 판정할 수 없었다. 난수 시드를 2004로 고정해 다시 비교한 결과, 검수본과 수정본 모두 오류 주입 없이 CPU에 패배 → 재경기 → 라이브 랠리 → 메뉴 복귀까지 통과했다. 수정본을 한 번 더 실행해 이 경로에서 페이지 오류와 프레임 복구 로그가 모두 0건임을 확인했다. 게임 배포본에는 시드 고정이 없고 테스트 도구에서만 사용한다.

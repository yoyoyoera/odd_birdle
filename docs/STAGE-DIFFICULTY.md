# Reddit 스테이지 난이도 측정

2026-11-19. `tools/stage-difficulty.mjs`의 `delayed-touch-lob-v1` 모델로 21개 스테이지를 각각 24회 측정했다. **자동 플레이어의 결과이며, 사람의 승률·플레이 시간 예측값이 아니다.**

## 재현

```sh
node tools/stage-difficulty.mjs --trials 24 --seed 20261119 --seconds 600
# 일부 스테이지만 다시 측정
node tools/stage-difficulty.mjs --trials 24 --seed 20261119 --seconds 600 --stages 1,4,19,20
```

게임은 고정 시뮬레이션 스텝 1/120초로 진행한다. 각 판의 최대 길이는 **시뮬레이션 시간 600초**다. 게임 난수와 플레이어의 조준·실수 난수는 별도 스트림을 사용한다. 각 스테이지/반복에 다른 결정적 시드를 주며, 같은 명령으로 재현할 수 있다. 측정 도구는 기존 CPU나 스테이지 설정을 수정하지 않는다.

## 플레이어 모델과 한계

- 10 Hz로 화면상의 셔틀 위치를 읽고 100 ms 뒤에 반응한다. 최근 두 관측으로 속도를 추정하며, 엔진의 미래 궤적 계산기·접촉 프레임·`canHit`를 이용하지 않는다.
- 손가락을 떼었다가 다시 놓고 약 160 ms 동안 연속 좌표로 올려치는 터치 동작이다. 조준 오차, 타이밍 오차, 6%의 한 번 쉬는 실수가 있다. 스트로크 이동량·속도는 제한되지만 손가락을 다시 놓을 위치까지 이동하는 비용은 없다.
- 주로 상대 코트의 같은 지점을 노리는 로브만 친다. 낮은 중력에서는 약한 스트로크로 보정한다. 스매시·드롭·상대 위치를 보고 바꾸는 전술·네트/범퍼별 공략은 없다. 따라서 공격이 잘 통하지 않는 후반부에는 긴 반복 랠리가 생긴다.
- DECOY가 보이면 관측의 25%에서 가짜를 따라가도록 근사한다. 실제 사람의 시각 추적 실험은 아니다.
- 상시 범퍼와 저중력은 실제 엔진 물리로 동작한다. 다만 다른 난수 시드를 쓰므로, 표의 두 행 차이를 해당 효과 하나의 인과적 차이로 해석하면 안 된다.
- 8·13·18·21번은 **실제 2v2가 아닌 문서의 싱글 대체 규칙**으로 측정했다.

## 판단과 후속 조정

첫 두 판은 이 방어적 로브 모델로도 쉽게 깬다. Lv.2부터는 단순히 되받아치는 것만으로 상대를 이기기 어려워지고, Lv.3 이후의 무효과 판에서는 이 모델의 공격 한계와 반복 랠리 편향이 지배적이다. 반대로 빈번한 효과나 범퍼는 랠리를 끊어 종료를 빠르게 하기도 한다. **후반의 0승을 사람이 클리어할 수 없다는 뜻으로 해석하지 않는다.**

이 측정만으로 CPU 레벨·목표 점수·효과 빈도를 임의로 낮추면 이미 조정된 CPU를 잘못 약화시킬 수 있어, 요청된 규칙표는 유지했다. 실제 Reddit 플레이에서 아래 사항을 우선 확인한 뒤 단계별로 조정한다.

1. 3번: 첫 5점 판이 초반에 너무 오래 걸리는지. 실제 초보 플레이도 길다면 목표 5→3을 우선 검토한다.
2. 6번: 한 점 승부 자체의 긴장감과 Lv.3 진입 난도가 적절한지. 반복 로브가 아닌 실제 공격으로 빠르게 끝나는지 본다.
3. 8번: 높은 네트 대체판에서 너무 오랫동안 되받아치기만 하는지. 필요하면 높은 네트 배율 또는 목표 점수를 낮춘다.
4. 12번: 0:4에서 다섯 점 연속 득점하는 도전의 재시도 부담. 전술을 익힌 플레이어의 성공률로 판단한다.
5. 14번: 저중력에 적응한 플레이어도 긴 랠리에 갇히는지. 먼저 목표 7→5 검토, 중력 테마는 유지한다.
6. 19·20번: 실제 사람이 설명을 읽고 효과/상시 범퍼를 구분할 수 있는지와 이벤트 가독성. 기계 모델의 종료 시간만 보고 빈도를 추가로 올리지 않는다.
